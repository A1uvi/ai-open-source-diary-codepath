# Rubric: is this pull request ready to submit?

Grade every check below, then apply the verdict rule. Read the plan before the diff and the diff before the description: the PR is only as good as what it actually changes and shows. Judge the diff, the output, and the claims themselves. Length, confidence, polish, and how many commits there are are not evidence.

## Checks

| Check | Evidence | Pass condition | Weight |
| --- | --- | --- | --- |
| diff-matches-plan | Every file and hunk in the diff, read against the plan's files, in-scope line, not-in line, and approach steps, plus any deviation note. | Every changed file and hunk is something the plan names or a recorded deviation explains, and every planned change (code, test, docs, changelog) is present in the diff. Fails when a hunk does work the plan never asked for or scopes out (a new option or flag, a rename, a refactor, a rewrite of a file the plan never touches), or when a planned piece is missing from the diff with no deviation note or disclosure. A planned piece left out and honestly disclosed (in the description or deviations) passes. | required |
| description-matches-diff | Each claim in the description (what changed, "implements the plan exactly", "docs updated", "no other changes", which files or behaviors) read against the diff. | Every claim is true of the diff. Fails when the description claims a deliverable the diff does not contain (a docs update that is not there, a fix for a path the diff does not touch) or denies something material the diff does contain ("no functional changes" over a new setting, "nothing beyond the plan" over an unplanned hunk). Loose counting or wording ("one function touched" when a helper is added for the same fix, a test count described slightly loosely) is not a failure. A description that is shorter than the diff but accurate passes. | required |
| repro-rerun-before-after | The test evidence, read against the plan's test plan and the repro steps. | The evidence re-runs the plan's repro (the same input, command, or scenario, including every failure mode the test plan names) and shows an observable before and after: a value, output, exit code, or state change, with the expected-after met. Fails when the evidence is only "tested locally", "works now", or "tests pass" with nothing named; when it exercises a different or unchanged path (the control, a different input, a case that never broke); or when the plan's named repro or a failure mode the test plan lists is never re-run. | required |
| repo-checks-run | The test evidence, read against the commands the repo's PR template, contributing guide, or repo-facts block ask contributors to run (tests, lint, typecheck, build). | The evidence names the repo's own test command or suite and states its outcome (a named command with a pass count or result counts; pasted output is better), or a check that could not run is named with the reason (an honest failure or an unrunnable check disclosed counts). Fails when no repo check is mentioned at all, or the outcome is a bare unnamed assertion ("tests pass", "all green", "works locally") with no command. Not every command the repo lists must appear: the test suite the change touches is the one that matters, and a lint or format step the evidence does not show does not fail this check. | required |
| diff-clean | The unified diff and the commit list: added lines, deleted lines, formatting-only hunks, and commit messages. | The change is visible and nothing unrelated rides along: no debug prints or leftover logging, no commented-out code, no dead or unused functions, no TODO notes on touched lines, no import reshuffles or re-indented or re-printed lines unrelated to the fix, no drive-by edits. Commit messages that say "wip", "misc cleanups", or "fmt + cleanup" over such hunks confirm it. Mechanical churn around a right fix still fails. | required |
| template-and-policy | The description read against the repo's PR template sections and the contribution policy in the repo facts (or, live, `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`). | Every section the template asks for has real content for this change (not left as the prompt text or empty), and every other explicit ask the repo states is met by the package: an issue reference such as `Closes #n` when asked, a changelog or whatsnew entry in the diff when the contributing guide requires one, tests when required, the required title format. If the repo has no template and states no asks, pass. | required |
| ai-disclosure | The repo-facts block's contribution policy (or, live, `docs/CONTRIBUTING.md` and the template), read against the description's own text. | Treat every package as AI-assisted work. If the stated policy requires disclosing AI use, the description must say so explicitly, in plain words, ideally naming the tool and the extent; a missing disclosure fails. If the policy sets only conditions short of disclosure (human in the loop, understanding the change, own-words comments) or says nothing about AI, pass; a description with no disclosure still passes then. An outright ban on AI-generated contributions fails. A description that merely reads as human-written never satisfies a stated disclosure requirement. | required |
| honest-shortfall | Any line in the description, notes, or plan deviations naming something left out, deferred, untested, or changed from the plan. | At least one real limitation or deviation is named specifically (what was left out and why, a check not run and why), or the package has none that the diff and evidence reveal. | preferred |

## Verdict rule

Accept only if every `required` check passes. `unclear` counts as `fail` on every check: a fact the package's own text does not let me decide is not evidence for either side, and a PR I cannot verify from its package is not ready to submit. `preferred` checks never change the verdict.

A PR that honestly discloses a shortfall (something deferred or not run, named with its reason in the description or deviations) is graded through the same checks as any other and accepts when it passes them. A polished PR with a perfect checklist and decisive evidence rejects on a single required failure, however complete the rest reads: when the description's claims or the diff's hunks fail the side-by-side read, that failure decides. Confidence is not a check; nothing in this rubric grades it.
